# 程序化手机盒装配

手机盒装配主界面使用统一的任务程序，目标是：手机完整进入盒内且朝向正确，盒盖对齐盖合，工具释放并撤离，物体保持稳定。流程图仍是“拿起手机 → 放入手机盒 → 盖上手机盒”，内部有26个动作和检查步骤。流程图点击用于查看子步骤，不会跳过正在执行的动作。

## 界面使用

1. 重启 EAI，进入“分阶段抓取”，选择“手机盒装配”。
2. 选择“MuJoCo 接触仿真”，点击“加载 / 复位仿真场景”。场景加载完毕后点击“运行装配”。无需先手动生成候选、张开手或逐段点击IK。
3. 可选择场景种子及轻微摆放扰动。仿真速率只改变播放墙钟速度，物理步长固定为2ms。
4. “暂停/继续”冻结/恢复仿真时间；“取消并保持”保留当前场景用于检查。取消不自动松手或跳回初始位置。重新开始使用单独的复位按钮。
5. “装配近景 / 机器人全景 / 透视验收”切换显示。透视只修改盒盖透明度，不改变碰撞或物体位姿；完成后仍可查看保存的三个视图。
6. “查看机器人页”可查看同步的A2D关节和对象包围盒。运行任务时禁用独立手型滑块，防止手动预览与任务控制混用。

原来的分段预览、IK、标定与手部控制保留在“高级分段调试 / 标定”中。其他任务仍使用原分段面板。复制手机装配任务会保留其程序类型。

## 程序与后端

- `phone_assembly/program.py`：与Qt、MuJoCo、ROS无关的任务逻辑。每个动作前从后端观测解析目标，动作完成后执行相应的状态检查；不是固定XYZ录像回放。
- `phone_assembly/mujoco_backend.py`：接触和重力驱动的手机、盒盖自由刚体；工具通过位置驱动与接触作用搬运物体。没有把手机/盒盖焊接到手上，也没有在执行过程中直接设置物体qpos。
- `phone_assembly/kinematics.py`：为接触工具映射A2D有界IK，腰部参与时保持另一只手的TCP，复检机器人本体与桌面、盒体、动态物体的采样碰撞。机械臂本身是运动学映射，不是关节动力学仿真。
- `phone_assembly/hardware_backend.py`：同一个任务程序对接现有6D估计、完整几何预检、独立执行服务和六维力保护。真机不加载MuJoCo或代理手参数。
- `phone_assembly/worker.py`：独立仿真进程；界面心跳延迟时暂停，持续丢失时退出。仿真工作进程明确拒绝真机模式。

## 仿真假设与验收

示例手机120×70×12mm，盒内132×82×25mm，盒体位于定位工装。工具为薄双指接触代理，**不是完整睿研手的接触模型**。这是可复现的装配程序基线，不能作为真实手指摩擦、驱动力或打印连接件强度的验证。

执行过程包含：夹持双侧接触检查、抬起后相对位姿检查、手机入盒与朝向检查、盖合位置/角度检查、释放和撤离检查、线速度/角速度稳定检查。手机进入盒内后采用小开口释放，再沿间隙撤离，避免完全张开时碰到盒壁。放置保留3mm示例释放高度，手指命令使用平滑开合，避免强压盒底。仿真接触载荷超限、低摩擦导致滑落、盒体尺寸不适配、IK/碰撞失败以及MuJoCo数值异常都会终止任务，不会继续把流程标绿。

## 真机复用

切换到真机后，绑定手机、盒体、盒盖三个现有视觉目标，并填写 `config/phone_assembly_hardware.json`。文件默认 `hardware_calibrated=false`，所有几何与手部实测项保留为空。

需要实测的关键参数：

- 手机和盒体/盒盖尺寸；视觉盒体坐标到内腔底面中心的 `T_box_frame_cavity`。
- Link7到任务工具TCP的 `T_link_tool`，及手机/盒盖的 `grasp_T_object_tool`。
- 手机、盒盖相对盒体的最终 `placement_T_reference_object`；可复用已标定的 `grasp_assembly.json` 对应关系，但位姿方法必须一致。
- 实际手型的张开、闭合、部分释放预设，以及驱动原始单位的速度/力参数。仿真代理的薄指间隙和N值不能转换成真实睿研电机值。
- 实际释放高度。若真实手指无法进入盒内，应标定盒口上方的释放姿态/高度，并验证落放过程，不要照搬3mm示例。
- 已标定的场景与连接件六维力保护，正确使能和持续的新鲜FK/手部/力反馈。

真机执行从空手、手机与盒盖位于盒外的初始工位开始。程序在关键动作前重新估计目标，真实手型通过实测反馈判断到位；夹持检查由操作员确认，放置检查使用新的视觉结果。手机在盖合前完成验收；盖合后被遮挡，不能声称再次看到了手机，若检测到盒体移动则要求重新检查。

仿真初始化采用右臂操作、非执行臂收拢的准备姿态，保留腰部补偿余量，随后保持非执行臂TCP。接近伸直的非执行臂可能让腰部联合IK无解，不能靠放宽误差解决。真机应先示教/核对合适的准备姿态；仿真初始化不会被直接下发给真机。

真机轨迹仍经过URDF限位、双TCP约束、采样碰撞、速度/加速度/jerk和工具速度检查。暂停、取消、心跳丢失和力保护由独立执行器处理。初始姿态不适合、目标不可见、手型不能实现或几何预检失败时会停止，不会改用仿真结果放行。

## 运行与记录

项目隔离环境依赖见 `requirements-grasp-ik.txt`，包含MuJoCo 3.3.7。离线运行不连接机器人：

```bash
MUJOCO_GL=egl .cache/grasp_ik_env/bin/python tools/run_phone_assembly.py \
  --output .cache/phone_assembly_validation/nominal --robot-ik --render

.cache/grasp_ik_env/bin/python tools/run_phone_assembly.py \
  --output .cache/phone_assembly_validation/seed_3 --seed 3 --randomize --robot-ik
```

界面记录位于 `.cache/phone_assembly_runs/<id>/`。包含场景XML、配置、软件版本/代码哈希、逐步事件、物体/机器人状态、最终验收结果和三个终态视图。真机任务记录位于 `.cache/phone_assembly_hardware_runs/`，各段底层执行记录仍位于 `.cache/grasp_service/`。

自动测试覆盖10个摆放/偏航扰动场景、低摩擦、尺寸不适配、数值故障注入、暂停/取消、界面完整运行，以及真机适配器的坐标转换、部分释放和迟到结果丢弃。真机适配器测试使用假传输，不代表已经进行实机装配。
